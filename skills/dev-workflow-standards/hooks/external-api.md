# 外部 API 请求

## 进入条件

准备向外部 API 发送指令、项目事实或生成/判断请求。只读分析不自动要求 API 调用；需要语义辅助时按 [工具协议](../references/openai-workflow-tools.md) 准备最小必要事实，避免重复分析。

## 执行条件

`check_api_input` 默认允许联网审核；它自身先做本地检查，不要求自我审核。完整用途和实际出站内容通过 [审核](../references/api-input-review.md) 后，当前任务必要的相同内容允许发送到既定配置服务。服务内部强制审核最终快照，不以公开预检豁免；私有审核路径仅豁免递归语义审核，本地检测仍执行。用户禁止外发优先。

每次实际 OpenAI 请求/重试从进程环境读取非空 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 并显式传 SDK；模型固定 `gpt-6-luna`，不回退。保留代理、脱敏、180 秒超时、默认仅超时重试 5 次与失败关闭规则。异步等待不改变审核依赖、权限或请求边界；取消停止后续阶段和重试，并有界释放客户端。

## 离开条件

成功：实际请求完成，结果通过所需结构/拒绝/完整性检查；建议和候选仍需核对，不能代替本地校验或发布授权。暂停：审核拒绝、不确定、配置缺失或请求失败；最终 `api_timeout` 已耗尽内部预算，不叠加整工具重试。

## 重新进入条件

用途、内容、策略或目的地变化时重新核对并按需重审。超时重试复用受检内容快照，但每次尝试重新读取配置；不得复用失效的通过结论。
