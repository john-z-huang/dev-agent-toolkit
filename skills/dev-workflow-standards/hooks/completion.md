# 完成交付与交接

GitHub 与 GitLab 托管仓库均适用；纯 Git 动作不要求 GitHub 登录，PR/MR 及平台工具差异见 [GitLab 兼容规则](../references/gitlab.md)。

## 进入条件

准备报告当前任务完成、交接或说明无法继续时适用。不因此新增提交、推送、清理或全仓审计。

## 执行条件

核对当前用户目标、允许范围和相关实际产物；验证由变更和项目要求决定。文档核对链接/引用，行为变更使用有意义的测试；Git/GitHub 状态只核对本任务涉及的资源。区分 PASS、FAIL、SKIPPED 和 BLOCKED，不将未执行标通过；Serena 诊断不替代测试。

合并后默认保留需求 worktree/分支；只有明确清理要求才适用 [清理条件](../references/pr-merge-cleanup.md)。分析任务以分析产物为交付，不要求生成代码或提交。

## 离开条件

完成：目标已满足，适用验证和实际副作用可核对，未验证项和限制明确。交接/暂停：目标未满足时说明已完成内容、剩余工作、证据和最小所需决定，不能宣称完成。

## 重新进入条件

目标、产物或检查结果变化，或获得解除阻塞的新事实。
