# Commit message 检查

需要起草提交信息时，先调用 MCP 工具 `generate_git_commit_message`。该工具固定复用 `generate_skill_content(kind="commit_message")`，不是新的模型调用路径，不执行 Git。提交 `user_request` 和结构化 `evidence`（本次选定的全部 patch/hunk、准确路径、前后行为及原因、实际验证与未运行项的来源），可用 `focus_questions`/`output_format` 指定重点和正文结构，无需先写完整正文。已暂存时先核对 cached diff；多 commit 按各自范围分别生成，不能只参考最后一次历史提交或混入整个 PR。用户已给完整 message 时直接保留原文检查，不强制生成。

返回 `candidate.title` 为完整标题、`candidate.content` 为可空正文，`message` 按标题、空行、非空正文拼接，可直接用于后续审阅和提交工具。`ok=true` 仅代表生成与本地引用/格式/署名校验成功；`validation_scope=local_format_and_attribution` 不等于语义审查通过。`adoptable=false` 或 `missing_facts` 非空时补证重新生成；通过也须按实际 staged diff 核对。该一次性接口不保存会话、无 Issue/PR 二次审查，联网经统一客户端与完整外发审核，固定模型和环境配置不变，不读 Git/文件、不写 Memory、不授予提交权限。

使用 MCP 工具 `check_commit_message`，以 `message` 字段传入最终完整提交信息（标题与可选正文），不只检查标题。标题必须符合 `<type>: 中文说明`，类型限于 `feat`、`fix`、`docs`、`refactor`、`test`、`chore`、`perf`、`build` 或 `ci`；标题需含中文说明；禁止 `Generated with`、`Generated by`、`Created with`、`Co-Authored-By` 等工具署名或生成声明。

检查只分析提供的文本，不读取或修改 Git，也不检查分支、暂存区或提交内容。它只检查署名/生成声明上下文，不屏蔽所有产品名字符串，以免误拦截合法技术说明或规则文档。

推荐通过项目的 `commit-msg` Hook 自动执行。Hook 脚本可以调用仓库中的兼容脚本；交互式 Skill 操作使用 MCP 工具。
