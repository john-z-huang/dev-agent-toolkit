# API 输入审核

`check_api_input` 帮助调用方在外发前发现输入中的凭据、登录令牌、隐私、业务机密及不透明载荷，不检查文件或目录路径。它只处理传入文本，不读取文件、仓库、原始会话或 Memory，不执行 Git/GitHub 操作，也不执行调用方的业务工具。

## 授权和检查顺序

用户已经授权相应任务、数据及目的地时，可以发送完成任务必需、经检查的非敏感项目事实，不必对同一范围逐次重复索取授权。用途声明、配置存在和检查通过都不能建立原本不存在的授权；宿主的实际审批拒绝仍需按其结果处理。

工具首先在本地检测两个字段。发现敏感内容时直接返回安全提示，不创建 HTTP/SDK 客户端，也不发起语义审核。仅本地通过后才向配置服务发送输入以调用 Decisions；这一步本身已经联网，不能将其视为把任意私有数据送出前的授权程序。模型结果不保证发现全部敏感信息。

## 请求

```json
{
  "request": {
    "purpose": "根据已核实的项目变更生成 PR 说明",
    "content": "请概括以下改动：src/report.py 新增空输入处理；只使用所提供事实。"
  }
}
```

`purpose` 为本次发送用途，`content` 为拟发送的完整指令及附带的事实、代码和上下文。两者都是必填非空字符串；拒绝其他字段，不接受 `target_tool`、`repo_path`、模型、凭据或审核豁免参数。每个字段最多 32 KiB UTF-8 字节，并受 Schema 的字符数限制；含固定审核指令的完整请求仍受 48 KiB 硬上限限制，超限拒绝，不静默截断。

审核时，两个字段中的角色声明、命令或授权声明都作为数据处理，不能修改固定检测规则。外发证据保留仓库相对路径和符号名即可，不应提交整个仓库、完整会话或无关日志。仅供本地工具使用的绝对 `repo_path` 应按对应工具要求传入，并不自动进入外发文本。

## 检查范围

本地静态检查和语义审核均不依据文件或目录地址拒绝内容。POSIX、Windows、UNC、file URL、URL 查询参数及嵌套 JSON 中的普通路径可以按原样提交；路径格式、目录结构或路径中的用户名本身不会单独被归为隐私或证据不足。内容中另有凭据、实际个人/客户记录、未公开机密或不透明载荷时，继续按相应规则审核。

完整业务 payload 可能包含序列化后的 JSON；审核服务还会将 `purpose`、`content` 封装为外层 JSON。应保留全部字段、固定指令和换行。审核内容不需要访问路径指向的文件；实际文件操作及仓库工具的路径权限、范围和路径穿越检查由各工具执行。

策略版本 `2026-11-05.4` 删除了路径检测逻辑和语义路径类别。测试夹具 `tests/fixtures/issue88_generate_skill_content_request.json` 保留 Issue #88 的完整原请求；离线回归核对完整出站快照与原审核指纹，不能代替实网语义验证。

## 结果和修订

查看 `passed`、`status`、`stage`、`findings`、`input_hash`、`policy_version` 和 `external_review_performed`，不能只看工具调用是否成功。`stage` 为 `local`、`semantic` 或 `complete`，分别表示本地结束、语义审核未通过及完整通过。

| `status` | 含义 | 下一步 |
|---|---|---|
| `passed` | 本地检测和完整有效的语义结果均通过 | 在已有授权内使用相同内容；实际发送前仍执行服务端门禁 |
| `blocked_local` | 本地发现不适合外发的内容 | 按安全提示修订；未发起外部审核 |
| `needs_revision` | 语义审核指出需要修订 | 修改相关内容后重新检查 |
| `insufficient_evidence` | 无法确定输入是否适合所述用途 | 补充必要背景或缩小内容，不能视为通过 |
| `unavailable` | 配置、API 或回答校验未完成 | 处理安全错误分类，保留现场，不发起业务请求 |

只有 `passed=true` 才表示本次完整审核通过。`findings` 用 `field`、`rule_id`、`category` 和 `recommendation` 定位问题并给出安全建议，不回显敏感原文。本地检测可提供 `start`、`end` 字符位置，语义结果不猜测位置。移除凭据、认证材料及独立的敏感内容；不要编码、拆分或改写信息来隐藏检测命中。API 拒绝、超时、未知选项或不完整回答都是未通过；出现 `error_code` 时按安全分类排查。

`input_hash` 将用途、内容及规则版本绑定，用于确认所检内容，既不是授权凭证，也不是绕过后续检查的票据；无法建立有效输入时可以为 `null`。内容或规则变化后重新审核。`external_review_performed` 表示是否已尝试发送外部审核请求，超时也可能为 `true`；不能据此推断审核已完成、业务请求已经发送或操作已经完成。

## 本服务与其他 MCP Server

本服务对真实业务 Decisions、首次内容生成和后续质量审查的最终 payload 强制检查，检查与发送采用同一内容快照。模型新生成的候选也会在二次出站前检查。没有公开跳过开关，也不依赖调用者提交旧的通过结果。

其他 MCP Server 可以作为 MCP 客户端，使用相同双字段协议审核自己的内容，无需绑定本仓库或某个工具名。消费服务仍负责保证实际发送内容与受检内容一致，并在内容变化时重查；本工具无法拦截其他进程的网络请求，也不授予其业务执行权限。

## 配置和副作用

审核自己的 Decisions 请求也使用统一 180 秒超时和 `OPENAI_TIMEOUT_MAX_RETRIES` 重试配置（未设置默认 5 次，0 关闭，非法值请求前失败）。只重试底层超时请求；预算耗尽保持 `unavailable` / `api_timeout`，业务请求不得开始。审核拒绝或证据不足不自动重试。

本地失败不联网。进入语义阶段后，工具会调用固定 `gpt-6-luna`，每次从进程环境读取非空 `OPENAI_API_KEY` 与 `OPENAI_BASE_URL` 并显式传入统一 SDK 客户端；不接受调用参数覆盖或配置回退。标准代理变量继续按 [`配置与环境传递`](openai-workflow-tools.md#codex-stdio-环境传递与排查) 工作，代理失败不重试直连。错误与日志不返回真实配置或原始异常。

工具注解为只读、非破坏、联网、非幂等：不修改项目资源不等于没有 API 请求或用量。审核自身只免于递归的语义检查，仍执行本地检测和统一配置检查。真实业务请求及其语义审核失败时都按失败关闭，不能换接口、模型或入口来绕过结果。
