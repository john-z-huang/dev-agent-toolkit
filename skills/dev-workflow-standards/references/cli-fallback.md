# MCP 优先与 CLI 补充

本规则同时适用于 GitHub 与 GitLab。GitLab 使用 `glab` 和显式主机/完整多级项目路径，HTTP 方法与正文传递见 [GitLab 兼容规则](gitlab.md#cli-能力缺口)，不照搬 `gh --repo` 或 GitHub API endpoint；实际失败仍禁止换入口绕过。

Code Agent 先检查当前可见的 MCP 工具及已授权 Connector 的能力、参数和副作用。能完整完成所需操作时优先使用；没有对应工具，或现有工具的功能、参数不能满足需求时，可在当前任务授权范围内自行选择相关 CLI、组合必要命令，无须仅因工具缺口再次请求人工授权。本规则同时适用于查询、文件操作、本地 Git 和 GitHub 写操作，不给 MCP 增加任意命令执行能力。

## 选择与停止条件

| 已观察情况 | 下一步 |
|---|---|
| 已暴露工具完整覆盖所需操作 | 使用对应工具及其参数 Schema，不为方便改走 CLI。 |
| 无对应工具、工具未暴露，或参数/功能未覆盖所需操作 | 核实缺口、目标和既有授权后，由宿主执行相关 CLI；只补足缺少的步骤，其余继续优先使用工具。 |
| 工具或服务实际发生连接、权限、认证、网络、仓库状态、参数校验或规则检查失败 | 保留现场，按[恢复条件](../hooks/recovery.md)处理原因；不得换 CLI、旧结果或兼容脚本跳过失败条件。 |
| 调用超时、部分成功或写入结果不明 | 先只读回读实际状态，确认已完成的效果；不得盲目重试、重复创建或用 CLI 覆盖。 |
| CLI 不可用、必要检查无法完成、目标/副作用不明，或缺少实际授权 | 停止依赖该条件的操作，报告具体缺口及最小所需决定；独立工作可继续。 |

“工具不支持部分 hunk 暂存”是能力缺口；“暂存工具拒绝路径穿越/范围不符”是校验失败。“没有首次添加 upstream 的工具”是能力缺口；“fetch 因认证失败”不是。不能把工具的安全限制或拒绝当成待补足的功能。

## CLI 执行要求

- 使用 `gh` 或访问 GitHub 的 MCP/Connector 前，先运行 `ghwho` 并遵循 [多账号核验](github.md#多账号核验)。账号查询和切换按该规则执行。
- 明确本次所需操作和工具未覆盖之处，核实绝对仓库根路径、目标文件/分支或远端 `owner/repo`。Git 使用 `git -C <根路径>`；gh 使用对应子命令支持的显式仓库参数或含仓库的 API endpoint。不依赖偶然的启动目录，不猜 remote URL、编号、维护基线或账号。
- 按完整命令、参数、配置和全部副作用判断读写。只读细节按 [`read-only-queries.md`](read-only-queries.md)；`fetch`、index/refs/配置修改和文件复制都是写入。复合命令的每一步分别满足前置条件，先后依赖的步骤依次执行并核验。
- 写入必须已被当前用户任务授权，并满足宿主 approval、沙箱和上级规则。既有授权在原范围内持续有效；换执行入口不扩大范围，也不豁免审批。新动作、破坏性效果或新业务决定缺少授权时才请求最小补充决定。
- 保留当前动作条件、适用门禁的检查目的和通过条件。门禁工具未暴露时，CLI 检查须覆盖同样的必要事实与规则，并核对实际结果；无法完成必要检查就停止，不把手工查询当作未运行的 MCP/API 校验通过。有工具时仍用工具，工具检查失败也不能降级绕过。
- 只修改授权范围，保留用户改动、正常 hooks、快进/非强推规则及已有保护。不因缺工具自动 clean/reset/stash、覆盖文件、删除资源、改写历史或跳过 hooks。兼容脚本须先核实用途、输入、实现与副作用，不能仅凭文件名执行。
- 不输出或保存凭据；错误只保留安全摘要。多行 Issue/PR 正文使用安全临时正文文件与 `--body-file`。OpenAI 相关检查继续遵守固定模型和环境配置规则，不通过 CLI 绕开 API 失败。
- 执行后回读目标、内容、状态及必要的 OID/路径集合，记录入口选择理由、实际验证和未完成项；不能以零退出码代替验收。结果不明时先核对现场，禁止自动补偿或重复写入。

## 常见能力缺口

| 需求 | 可以在既有授权内补足的步骤 | 必须保留的条件 |
|---|---|---|
| 首次配置 upstream、维护分支基线或 tracking | 核实目标后用 Git CLI 配置，再回读 | Fork parent、准确 URL/基线、用户改动与快进同步规则。 |
| 同文件只有部分 hunk 属于本任务 | 用 Git CLI 精确暂存所需 hunk，再核对完整 staged diff | 暂存/提交授权；不混入无关 hunk；后续检查及提交工具仍优先使用。 |
| 安装 Hook 文件、恢复跨 worktree 的未跟踪文件 | 核实来源、目标与指纹后复制，再核对 | 不覆盖已有内容；核验 symlink/特殊文件；配置 Hook 优先用已有工具。 |
| 修改 PR base、revert 或 branch protection/rulesets | 用 Git/gh CLI 执行已授权修正并回读 | 先解决已发现的策略问题，再重新审计；不绕过权限或保护。 |
| 空远端初始化 | 按已确认的最小 bootstrap 用 CLI 建立基线 | 不混入需求内容；确认默认分支/PR base 后再重新核对动作条件。 |
| 检查/升级本机 Serena 或历史标题维护 | 按对应参考文档核实来源、范围，再使用相关 CLI/已审阅脚本 | 检查不自动升级；升级、历史改写等仍需各自授权。 |

本规则只调整 Agent 的入口选择，不实现命令解析、隔离、审批或新的 MCP 功能。仓库修改不会自动更新用户全局 AGENTS、已安装 Skill 或运行中服务；上层限制仍须遵守并如实报告。
